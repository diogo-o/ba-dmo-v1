# Coder execution rules

## A. Canonical HTML is the visual target

Do not redesign. Do not simplify. Do not create temporary test layouts. Do not move actions merely because the coder prefers another structure.

## B. HTML controls presentation

HTML controls page anatomy, hierarchy, section order, tabs, sidebar placement, cards, visible controls, interaction placement and responsive composition.

## C. Functional SOT controls behavior

If functional authority conflicts with mockup/demo behavior, functional behavior wins. Stop and report the conflict.

## D. Mockup data is not business logic

Never copy demo IDs, demo data, fake JavaScript, fake calculations, fake API calls, inline hardcoded state, local paths or mock authentication.

## E. No broad design search

Use the curated module package. Do not search the entire design folder for alternatives. If something essential is missing, stop and report it.

## F. No schema redesign

Do not change database/schema because HTML needs more data. First prove the existing read contract cannot supply it. Then use the smallest additive read DTO/query only if allowed.

## G. Screenshot acceptance is mandatory

Required viewports: 1440×900, 980×900, 720×900 and 375×812.
